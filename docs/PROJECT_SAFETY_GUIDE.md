# Do Not Touch List – Project Safety Documentation
### Files & Directories Developers Should Not Edit (Strict)

This document lists **files and folders that developers should treat as generated, vendor, or infrastructure output** and therefore **should not be edited directly**.

For each entry you get:
- **What it is**
- **Why it exists (one sentence)**
- **Strict rule** (hands off vs. rare exception)

> ✅ Safe rule of thumb: **Edit `src/` and docs only. Everything else is tooling, output, or dependencies.**

---

## 1) `node_modules/` (Directory) — DO NOT TOUCH

**Why it exists (1 sentence):** Contains all third‑party packages installed by npm so the project can build/run without bundling libraries into the repo.

**Rule:** Never edit; it is fully regenerated by `npm install`.

---

## 2) `dist/` (Directory) — DO NOT TOUCH

**Why it exists (1 sentence):** Holds generated build output (compiled JS and generated Tailwind CSS) that the browser actually loads.

**Rule:** Never edit; it is regenerated by TypeScript + Tailwind build steps.

---

## 3) `dist/styles.css` (File) — DO NOT TOUCH

**Why it exists (1 sentence):** Tailwind’s generated CSS output containing only the utility classes used in the project.

**Rule:** Never edit; change styling by editing Tailwind class strings in `src/`.

---

## 4) `dist/**/*.js` and `dist/**/*.map` (Files) — DO NOT TOUCH

**Why it exists (1 sentence):** Compiled JavaScript and source maps produced from TypeScript so the browser can execute the app and debugging can map back to `src/`.

**Rule:** Never edit; update `src/` and rebuild instead.

---

## 5) `package-lock.json` (File) — DO NOT TOUCH (Manually)

**Why it exists (1 sentence):** Locks the exact dependency versions installed to ensure reproducible builds across machines and time.

**Rule:** Never hand-edit; let npm manage it (`npm install`, `npm update`, `npm ci`).

---

## 6) `*.tsbuildinfo` (File) — DO NOT TOUCH

**Why it exists (1 sentence):** TypeScript incremental build cache that speeds up recompilation during development.

**Rule:** Never edit; safe to delete if you need a clean build.

---

## 7) `.env` / `.env.*` (Files) — DO NOT TOUCH (in shared repos)

**Why it exists (1 sentence):** Stores machine-specific or secret configuration like API keys and environment variables.

**Rule:** Do not commit; do not share; keep local only and use `.env.example` for templates.

---

## 8) Editor / OS Metadata (Files) — DO NOT TOUCH

### `.DS_Store` / `Thumbs.db`
**Why it exists (1 sentence):** Operating system metadata files created automatically by macOS/Windows file explorers.

**Rule:** Never commit; ignore in Git.

### `.vscode/` (Directory)
**Why it exists (1 sentence):** Editor-specific settings for Visual Studio Code.

**Rule:** Do not rely on it for build logic; optionally commit only curated settings if the team agrees.

---

## 9) Build/Tooling Output (If Present) — DO NOT TOUCH

### `.cache/`, `.tmp/`, `.temp/`
**Why it exists (1 sentence):** Temporary caches created by tools to speed up rebuilds or store intermediate artifacts.

**Rule:** Never edit; safe to delete if troubleshooting.

---

## 10) “Configuration files” – Edit only with intent (Not day-to-day)

These are not “never touch”, but they are **infrastructure** and should be changed only deliberately:

- `tsconfig.json` — TypeScript compiler rules  
- `tailwind.config.js` — Tailwind scanning + design system  
- `postcss.config.js` — CSS processing pipeline  

**Why they exist (1 sentence):** They control how code is compiled and how Tailwind CSS is generated, affecting the entire project.

**Rule:** Change only when you understand impact; review changes carefully.

---

## Summary: Safe Editing Zones

✅ OK to touch daily:
- `src/**`
- documentation (`README.md`, `docs/**`)
- static assets you own (`assets/**`, if present)

🚫 Do not touch:
- `node_modules/**`
- `dist/**`
- generated caches and lock artifacts

---

## If Something Looks Wrong

If you suspect generated output is stale, do **not** edit it — rebuild it:

```bash
npm install
npm run dev
```

If you need a hard reset:

```bash
rm -rf node_modules dist
npm install
npm run dev
```

(Windows PowerShell equivalents differ.)
